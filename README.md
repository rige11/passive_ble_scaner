# Пассивный BLE-сканер на базе ESP32-C3 с автоматическим логированием

Проект представляет собой выполнение тестового задания. Система состоит из двух компонентов: прошивки для микроконтроллера ESP32-C3, которая пассивно сканирует BLE-эфир, и кроссплатформенного Python-скрипта, автоматически сохраняющего логи на компьютер с формированием небольшого аналитического отчета.


### ESP32-C3

*   **Режим работы:** **Passive Scan (`setActiveScan(false)`)**. Радиомодуль контроллера работает исключительно на прием (Listen) и не отправляет запросы `SCAN_REQ`. Устройство полностью невидимо в эфире и не тратит энергию на передачу (TX).
*   **Ограничение по времени:** Использован программный таймер на базе `millis()`. Ровно через 10 минут (600 000 мс) сканирование аппаратно останавливается.
*   **Оптимизация памяти:** После каждой итерации вызывается метод `pBLEScan->clearResults()`. Это важно для предотвращения переполнения оперативной памяти (Out of Memory) из-за лавинного накопления уникальных пакетов в плотном эфире.
*   **Фильтрация данных:** Внедрен программный фильтр дубликатов на уровне Callback-функции для исключения мгновенного повторного вывода идентичных пакетов.

### Скрипт захвата и аналитики (Python)
*   **Авто-обнаружение:** Скрипт сканирует COM-порты системы и находит плату по её уникальным заводским идентификаторам (Vendor ID: `303A`, Product ID: `1001`), исключая ручной ввод порта.
*   **Авто-сброс (Auto-Reset):** При подключении скрипт программно дергает линии DTR/RTS, автоматически перезагружая плату. Отсчет 10 минут начинается строго в секунду запуска скрипта на ПК.
*   **Формирование отчета:** Скрипт накапливает сырой лог в оперативной памяти ПК, а по завершении 10-минутного таймера генерирует аналитическую статистику и записывает её в **самое начало** итогового файла.

## Формат вывода данных (UART, 115200 baud)

Лог выводится в структурированном виде:
`ADDR: [MAC] | TYPE: [0-3] | RSSI: [dBm] | PAYLOAD: [HEX-строка]`

*   **ADDR:** MAC-адрес устройства.
*   **TYPE:** Тип адреса по спецификации BLE (`0` — Public, `1` — Random для защиты от отслеживания).
*   **RSSI:** Уровень принимаемого сигнала в дБм (индикатор расстояния до источника).
*   **PAYLOAD:** Сырые байты данных пакета в формате EIR (Advertising Data Structure), разбитые по блокам `[Длина] [Тип] [Данные]`.

### 1. Выбор параметров сканирования (`Scan Interval` = 100 мс, `Scan Window` = 50 мс)
Выбран сбалансированный режим со скважностью (Duty Cycle) 50%. Приемник активен половину времени интервала, циклически переключаясь между тремя рекламными каналами (37, 38, 39). Это оптимальный компромисс для  embedded-устройств между вероятностью поимки пакетов и энергоэффективностью (снижает нагрев и потребление чипа в два раза по сравнению с непрерывным сканированием 100/100).

### 2. Возможен ли пропуск пакетов при перестройке частоты на приемнике?
**Да, пропуск пакетов происходит неизбежно.** Он вызван двумя факторами:
1.  *Аппаратный (PLL Lock Time):* При смене канала синтезатору частоты требуется от нескольких десятков до сотен микросекунд для стабилизации. В это мгновение радиомодуль «слеп».
2.  *Вероятностный (Blind Spot):* Поскольку у SoC всего одна антенна и один радиомодуль, мы можем слушать только одну частоту одновременно. Если передатчик вещает на 38-м канале, а наш сканер в это время открыл окно на 37-м или находится в фазе «отдыха» между окнами, пакет будет пропущен. Потеря пакетов компенсируется временной избыточностью — за 10 минут наблюдения окна приемника и передатчиков гарантированно совпадают сотни раз.

### 3. Поведение сканера при интерференции от мощного Wi-Fi роутера (2.4 ГГц)
Широкополосный Wi-Fi сигнал (20/40 МГц) создает сильный шум на центральных частотах диапазона. Если роутер работает, например, на 6-м канале Wi-Fi, это приведет к частым коллизиям и разрушению CRC-пакетов на **38-м рекламном канале BLE**. Однако, благодаря тому что рекламные каналы 37 и 39 разнесены по самым краям спектра 2.4 ГГц (вне зоны покрытия центральных Wi-Fi каналов), сканер продолжит успешно агрегировать дублирующиеся пакеты на этих двух частотах.

## Инструкция по запуску

1.  Прошивка ESP32-C3 через Arduino IDE (в `Tools` укажите **USB CDC On Boot - Enabled**).
2.  **Закройте Монитор порта в IDE**, чтобы освободить порт.
3.  Установите зависимость: `pip install pyserial`
4.  Перейдите в папку python : `log_ble.py`
5.  По истечении 10 минут скрипт выведет итоговую таблицу, а структурированный лог появится в корневом каталоге проекта под именем `esp32_ble_log.txt`.
